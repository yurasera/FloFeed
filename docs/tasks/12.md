Create feedback storage abstraction.

Goal:
Prepare FloFeed feedback data architecture for future backend integration.

Flow:

Feedback:
1. User completes anonymous feedback flow
2. Submit feedback data through FeedbackService
3. Store feedback using mock implementation
4. Retrieve feedback data for class analysis
5. Generate feedback summary


Create:

Data Models:
- FeedbackResponse
- FeedbackSummary

TypeScript interfaces:

FeedbackResponse:
- id
- classId
- selectedMood
- reflectionAnswers
- createdAt

FeedbackSummary:
- classId
- totalResponses
- moodDistribution
- commonReflection


Service Architecture:

UI
↓
Custom Hooks
↓
FeedbackService
↓
Mock Implementation
↓
Future Supabase Implementation


Create:

FeedbackService interface:

Functions:

- createFeedback()
  - Save anonymous feedback response
  - Return created feedback data

- getFeedbackByClass()
  - Retrieve feedback responses by classId
  - Return list of feedback responses

- getFeedbackSummary()
  - Process feedback responses into summary data
  - Return aggregated feedback insights


Requirements:

- Create FeedbackService interface.
- Create MockFeedbackService implementation.
- Separate service logic from UI components.
- Use TypeScript interfaces for all data models.
- Keep anonymous feedback behavior.
- Ensure feedback does not store learner identity.
- Prepare service contract for future Supabase replacement.
- Keep existing feedback flow working.
- Allow future mentor dashboard to consume feedback summary.


Constraints:

- Frontend only.
- No database.
- No authentication.
- No API calls.
- No external services.
- No unnecessary dependencies.
- Use mock data only.
- Do not modify existing feedback UI unnecessarily.
